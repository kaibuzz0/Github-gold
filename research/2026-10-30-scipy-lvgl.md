## 1. SciPy — VERIFIED (upstream) / S28
- Repository: https://github.com/scipy/scipy (SciPy contributors).
- Stable: https://github.com/scipy/scipy/releases/tag/v1.18.1 published 2026-08-21. The v1.18.1 `pyproject.toml` requires Python >=3.12 and NumPy >=2.0,<2.8. The main-branch manifest now declares **2.0.0.dev0**, not another stable release.
- Core license: BSD-3-Clause `LICENSE.txt`; `LICENSES_bundled.txt` enumerates separately licensed native components. Do not assume every subproject inherits the root license.
- Exact reusable modules: `scipy/signal/_peak_finding.py` (peak detection), `scipy/signal/_spectral_py.py` (spectral estimators), `scipy/spatial/_ckdtree.pyx` (nearest-neighbor spatial index), `scipy/optimize/_linprog_highs.py` (HiGHS LP bridge), `scipy/optimize/_milp.py`, `scipy/sparse/csgraph/` (sparse graph algorithms), `scipy/integrate/`, `scipy/fft/`. Inspected `scipy/signal/tests/`, `scipy/spatial/tests/`, `scipy/optimize/tests/` and Meson/Cython package metadata.
- **Passing evidence:** 2026-10-30 main SHA `37b447f8746d2d44d25ca98034c186db2a520c04`, [Linux tests 41117526122](https://github.com/scipy/scipy/actions/runs/41117526122) passed **15/15 jobs**, including Linux/aarch64, free-threaded and native-build scenarios; [CodeQL 41117526068](https://github.com/scipy/scipy/actions/runs/41117526068) passed.
- **Failing evidence:** [Same-commit Emscripten/Pyodide 41117526067](https://github.com/scipy/scipy/actions/runs/41117526067) compiled but failed pytest execution after a plugin import attempted `from os import geteuid` under WebAssembly (`ImportError`). This is an upstream SciPy test-environment failure; it does not establish a numerical kernel regression, and does not establish Pyodide main CI status. [2026-10-27 Emscripten/Pyodide run 40562698528](https://github.com/scipy/scipy/actions/runs/40562698528) had succeeded.
- **Related:** numpy/numpy runtime; ERGO-Code/HiGHS optimization subproject; scientific-python/array-api-compat; pyodide/pyodide (cross-platform integration pathway). Existing Pyodide catalog entry cross-linked with explicit caveat.
- **Limits/follow-up:** Numerical tolerances, input-size/memory limits, platform ABI and bundled native libraries; reproduce `os.geteuid` pytest-plugin failure, distinguish build from runtime test, confirm stable-tag Pyodide wheel behavior. No independent calculations performed.

## 2. LVGL — VERIFIED (upstream) / S27
- Repository: https://github.com/lvgl/lvgl (LVGL contributors).
- Stable: https://github.com/lvgl/lvgl/releases/tag/v9.6.0 published 2026-09-16. Current `library.properties` declares 9.6.0.
- License: MIT `LICENCE.txt` for core. `COPYRIGHTS.md` and `sbom/` list distinct third-party licenses for bundled codecs, fonts and demos (e.g., OFL font, BSD/Zlib libraries). Optional LVGL Pro design/editor tooling has different terms and must not be treated as MIT core.
- Exact reusable modules: `src/core/lv_obj.c` and `lv_obj_event.c` (object/event model), `src/display/lv_display.c` (display refresh), `src/draw/lv_draw.c` (render pipeline), `src/widgets/`, `src/layouts/flex/`, `src/indev/lv_indev.c` (input), `src/drivers/` (platform backends), `examples/`, `tests/main.py` and `tests/src/test_cases/`. ESP-IDF integration manifest `idf_component.yml`; Zephyr `zephyr/module.yml`.
- **Passing evidence:** 2026-10-30 master SHA `9373f7cd196b365c23b5370240d3db02251e1203`, [Build and Test 41121901026](https://github.com/lvgl/lvgl/actions/runs/41121901026) passed **12/12 jobs**, including Linux/Windows configurations, 32/64-bit tests, ESP-IDF ESP32-S3 **build**, and NuttX **build**. This is not ESP32 hardware testing.
- **Failing evidence:** [Emulated Performance Test 41121901043](https://github.com/lvgl/lvgl/actions/runs/41121901043) had 32-bit benchmark success but 64-bit Docker image layer failed with `no space left on device` (exit 125). [Build Docs 41121901212](https://github.com/lvgl/lvgl/actions/runs/41121901212) failed during `doxymark` npm install with `SyntaxError: Unexpected token '?'`; no indication these failures came from the core rendering test suite.
- **Recursive ecosystem finding:** `zephyrproject-rtos/zephyr` `west.yml` uses default remote `https://github.com/zephyrproject-rtos`, and pins `lvgl` to commit `c9ffd4692de246eb911c7ba49b78a331b2c63c74` at `modules/lib/gui/lvgl`. The commit was found in [zephyrproject-rtos/lvgl fork](https://github.com/zephyrproject-rtos/lvgl/commit/c9ffd4692de246eb911c7ba49b78a331b2c63c74), **not** upstream lvgl/lvgl. Zephyr `modules/lvgl/Kconfig` provides `LVGL` enablement; no hardware/display interoperability test. Also inspected LVGL's `zephyr/module.yml`, `idf_component.yml` and companion repos `lvgl/lv_micropython`, `lvgl/lv_port_esp32`.
- **Limits/follow-up:** Confirm pinned fork API/version compatibility, renderer/display-driver memory safety, RAM/flash consumption and physical-device input/refresh. Investigate npm `doxymark` dependency and Docker runner disk constraints; passing core CI does not prove performance or docs health.
