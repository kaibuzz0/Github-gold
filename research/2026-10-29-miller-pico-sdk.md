# Miller and Raspberry Pi Pico SDK — evidence-led GitHub-first research (2026-10-29 UTC)

## Provenance and method
Two distinct domains were investigated: command-line structured-data processing and RP-series embedded firmware. Sources were upstream GitHub READMEs, release metadata, license files, manifests, source trees, CI workflows and actual job-step results. No new YouTube playlist transcript data was obtained; the six earlier playlist seeds remain unverified. No third-party code copied, and no independent build, tool execution, hardware flashing or security audit performed.

## Miller — VERIFIED upstream / S28
- Repository: https://github.com/johnkerl/miller ; [root BSD-2-Clause license](https://github.com/johnkerl/miller/blob/main/LICENSE.txt). Stable [v6.22.0](https://github.com/johnkerl/miller/releases/tag/v6.22.0), published **2026-09-25**, adds Unicode-boxed output, XDG configuration and `datediff` DSL support. Inspected current `go.mod` specifies Go 1.26.10.
- **Upstream execution evidence:** [2026-10-27 Miller-Go run 40522448049](https://github.com/johnkerl/miller/actions/runs/40522448049) at main SHA `d035f6f56e4321ef0a07636614f4168c19bfe558` passed **3/3** Linux/macOS/Windows jobs. Each ran `make build`, `make unit-test` and `test/../mlr regtest -S`. CodeQL, golangci-lint and Codespell also passed on main. These are upstream CI claims, not our execution.
- **Exact reusable components:** [CSV reader](https://github.com/johnkerl/miller/blob/main/pkg/input/record_reader_csv.go) checks separators and streams records via channels; `pkg/input/record_reader_json.go`; `pkg/output/record_writer_json_jsonl.go`; `pkg/mlrval/mlrmap.go` insertion-ordered records; `pkg/dsl/cst/` expression engine; `pkg/transformers/{join,stats1,reshape,put_or_filter}.go`; `pkg/bifs/`; `test/` and `regression_test.go`.
- **Licensing caveat:** Root BSD-2-Clause is not universal: [`pkg/go-csv/LICENSE`](https://github.com/johnkerl/miller/blob/main/pkg/go-csv/LICENSE) retains a distinct Go Authors BSD-3-Clause-style notice. Check all file and dependency licenses before reuse.
- **Architecture comparison:** Existing [jq](https://github.com/jqlang/jq) specializes in JSON filters; Miller handles heterogeneous CSV/TSV/JSONL records. [Nushell](https://github.com/nushell/nushell) provides typed shell pipelines; no direct integration asserted. Current `go.mod` imports [johnkerl/lumin](https://github.com/johnkerl/lumin).
- **Limitations:** Not all verbs have bounded memory; sorting, joins and grouping can retain state. No independent malformed-input fuzzing, benchmarks, Termux execution or prepipe/config security review.
- **Score:** 5 utility + 5 working evidence + 5 reusability + 4 novelty + 5 documentation + 4 maintenance = **28 (S)**.
- **Next:** CSV/JSONL round-trip and malformed-input tests, memory scaling, DSL/prepipe trust boundary, Termux portability.

## Raspberry Pi Pico SDK — VERIFIED upstream / S27
- Repository: https://github.com/raspberrypi/pico-sdk ; [root BSD-3-Clause license](https://github.com/raspberrypi/pico-sdk/blob/master/LICENSE.TXT). Stable [2.3.1](https://github.com/raspberrypi/pico-sdk/releases/tag/2.3.1), published **2026-09-04**. README documents `master` as stable and `develop` as upcoming changes.
- **Exact reusable components:** [PIO state-machine management](https://github.com/raspberrypi/pico-sdk/blob/master/src/rp2_common/hardware_pio/pio.c); [DMA channel/timer claiming](https://github.com/raspberrypi/pico-sdk/blob/master/src/rp2_common/hardware_dma/dma.c); `src/rp2_common/hardware_flash/flash.c`; `src/rp2_common/pico_multicore/`; `src/boards/include/boards/`; RP2040/RP2350 boot-stage2; `pico_sdk_init.cmake` and `external/pico_sdk_import.cmake`.
- **Build evidence:** [2026-10-29 CMake run 40919233317](https://github.com/raspberrypi/pico-sdk/actions/runs/40919233317) passed on PR SHA `46ac1d535c727a81e7ec39d81c83530a593804a5`. The self-hosted Linux runner initialized submodules, configured with `PICO_SDK_TESTS_ENABLED=1`, and built. Bazel/config/extern-C checks on the same PR also passed. This does **not** prove that CTest ran or that any board executed firmware.
- **Contrary evidence:** [2026-10-29 develop macOS run 40865066254](https://github.com/raspberrypi/pico-sdk/actions/runs/40865066254) failed at **Install dependencies**; native/project build steps were skipped. It is neither a successful macOS build nor proof of a source compile failure.
- **Licensing and recursive ecosystem:** [`.gitmodules`](https://github.com/raspberrypi/pico-sdk/blob/master/.gitmodules) directly references [TinyUSB](https://github.com/hathach/tinyusb), [CYW43 driver](https://github.com/georgerobotics/cyw43-driver), [lwIP](https://github.com/lwip-tcpip/lwip), [mbedTLS](https://github.com/Mbed-TLS/mbedtls), [BTstack](https://github.com/bluekitchen/btstack). Each submodule has separate license/security obligations. Official [pico-examples](https://github.com/raspberrypi/pico-examples) and [pico-extras](https://github.com/raspberrypi/pico-extras) exist but were not built.
- **Runtime:** CMake >=3.13, Python 3, Arm cross-compiler and RISC-V toolchain for relevant RP2350 targets, submodules, and physical board for firmware execution.
- **Limits:** No independent build, CTest, RP2040/RP2350 board flashing, PIO/DMA timing or safety validation.
- **Score:** 5 utility + 4 working evidence + 5 reusability + 4 novelty + 5 documentation + 4 maintenance = **27 (S)**.
- **Next:** Reproducible official example builds, RP2040/RP2350 feature differences, USB integration and submodule license/SBOM review.
