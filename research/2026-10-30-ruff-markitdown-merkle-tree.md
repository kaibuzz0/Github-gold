- **Upstream execution evidence:** [2026-10-28 PR-branch tests run 40717145636](https://github.com/microsoft/markitdown/actions/runs/40717145636) **21/21 passed**, covering Python 3.10–3.14 Ubuntu, Windows x64/ARM, core converters, OCR and MCP. Tests workflow triggers on pull requests, so this does **not** prove current-main or exact v0.1.9 release testing. [2026-10-30 `fix/zip-bomb-dos-protection` workflow 41026922728](https://github.com/microsoft/markitdown/actions/runs/41026922728) was `action_required`; neither passing tests nor a shipped fix were established.
- **Security observation (source, not exploit reproduction):** ZIP converter iterates `ZipFile.infolist()`, calls `zipObj.read(entry)` **without a per-entry uncompressed byte bound**, stores bytes in `io.BytesIO`, and recursively calls `convert_stream`. This creates plausible memory/CPU exhaustion with untrusted or deeply nested archives. The code does not visibly impose cumulative extraction limits. Apply process isolation, memory/time/file size, recursion and entry-count caps before use with untrusted ZIP. Do not claim a confirmed vulnerability severity or a tested exploit.

Utility 5 + Working Evidence 4 + Reusability 4 + Novelty 3 + Documentation 5 + Maintenance 4 = **25/A**. Core local conversions possible, but URL fetches, cloud services and third-party plugins can access privileged resources or transmit data. Dependencies and plugin terms separately licensed.
