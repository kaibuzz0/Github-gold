## Obtainium — VERIFIED upstream / S26
- Canonical repository: https://github.com/ImranR98/Obtainium ; GPL-3.0 root LICENSE.txt.
- Release v1.7.3 published 2026-10-25: https://github.com/ImranR98/Obtainium/releases/tag/v1.7.3 ; release assets include architecture-specific and universal APKs, SHA-256 files and detached signature files. Their presence is not independent signature verification.
- Source requirements in `pubspec.yaml`: Dart ^3.12.0, Flutter >=3.44.0. Android is the target. Pinned installer dependency forks `ImranR98/android_package_installer` and `ImranR98/android_package_manager` require independent licensing/maintenance review.
- Upstream 2026-10-25 workflow: https://github.com/ImranR98/Obtainium/actions/runs/40148046321 ; its build job succeeded, including `Build APKs` and `Create Draft Release`. Workflow source https://github.com/ImranR98/Obtainium/blob/main/.github/workflows/release.yml explicitly builds **unsigned** APKs and signs separately. No verified end-to-end update/installation test was observed.
- Reusable upstream locations: `lib/app_sources/github.dart` implements release selection (draft/prerelease exclusion and asset dates); `lib/app_sources/{gitlab,fdroid,codeberg}.dart` implement other sources; `lib/providers/apps_provider_updates.dart` coordinates updates; `lib/installers/{stock,shizuku,root}_installer.dart` models privilege-specific installers.
- Security-oriented locations: `lib/utils/signing_cert_utils.dart` hashes APK signer certificates, handles multiple signers and signing history; `lib/services/pinned_certificates.dart` manages pinned certificates. `test/github_release_filter_test.dart`, `test/pinned_certificates_test.dart`, `integration_test/signing_cert_test.dart` exist but their execution was **not** established by the inspected release workflow.
- Compare with existing MuntashirAkon/AppManager: Obtainium is primarily upstream release discovery and installation; App Manager focuses on installed-app inspection, component management and diagnostics. Complementary, no direct integration asserted.
- Risks: app-source spoofing, signer rotation, APK provenance, third-party installer privileges, release-asset matching, update downgrade behavior. Published checksums are not proof of publisher identity. Review GPL-3.0 and file/dependency notices before reuse.
- Follow-up: run a controlled Android update test, verify actual release signatures and certificate lineage, inspect dependency-fork licensing and runtime permission handling, check unit/integration test execution in CI.

## Litestream — PROMISING / A25
- Canonical repository: https://github.com/benbjohnson/litestream ; Apache-2.0 root LICENSE. Stable v0.5.17 published 2026-08-31: https://github.com/benbjohnson/litestream/releases/tag/v0.5.17 . Release notes explicitly state Windows binaries are **not officially supported**.
- Inspected main `go.mod` uses Go 1.26.0/toolchain 1.26.10 and includes `github.com/nats-io/nats.go`, `github.com/superfly/ltx`, and cloud storage SDKs.
- Reusable upstream locations: `db.go` and `wal_reader.go` for SQLite WAL processing; `replica_client.go` for backend abstraction; `s3/replica_client.go`, `gs/replica_client.go`, `abs/replica_client.go`, `sftp/replica_client.go`, `webdav/replica_client.go` for replica backends; `cmd/litestream/restore.go` for recovery; `vfs.go` and `src/litestream-vfs.c` for VFS; `tests/integration/` for scenarios.
- Direct ecosystem evidence: https://github.com/benbjohnson/litestream/blob/main/nats/replica_client.go imports `nats.go/jetstream`, registers the `nats` replica client factory and uses JetStream Object Store. This is a **Litestream client integration**, not a feature built into NATS Server.
- CI evidence, 2026-10-29: PR SHA `8004de35575ef243ac46ba3db3ebd7ea5662f9de` https://github.com/benbjohnson/litestream/actions/runs/40930723107 passed core unit, VFS, mock S3, MinIO, WebDAV, SFTP and NATS jobs, but live S3/R2/Azure/GCP jobs were skipped. PR https://github.com/benbjohnson/litestream/actions/runs/40930723154 passed quick integration jobs, skipped long-running and scenario jobs. PR https://github.com/benbjohnson/litestream/actions/runs/40930723142 passed a v0.3-to-v0.5 upgrade job.
- Contradictory current-main evidence: SHA `fb9c163bb2dc877a1b121bff20f9e4bdeeebec96`, https://github.com/benbjohnson/litestream/actions/runs/40929579845 **failed** GCP and S3 integration jobs, although unit/VFS and several other backend jobs passed. Do not call main green or infer the PR passed on main.
- README documents a source database `_litestream_lock` table used for WAL checkpoint synchronization. Database files are not necessarily byte-identical to pre-Litestream files. Backup success must be checked with actual point-in-time restoration and integrity validation.
- Risks: storage credentials, WAL growth, cloud consistency, missed checkpoints, retention, corruption and restore divergence, VFS concurrency and experimental features. Cloud integration failures may be environmental but are not proven benign.
- Follow-up: investigate GCP/S3 failure logs and fixes; run deterministic crash-and-restore against a disposable SQLite DB; test NATS JetStream backend against scoped accounts, TLS, quotas and object retention; compare with Kopia at the recovery-model level, not as a replacement.
