## ArduinoJson — VERIFIED upstream / S27
- **Upstream:** https://github.com/bblanchon/ArduinoJson ; [MIT LICENSE.txt](https://github.com/bblanchon/ArduinoJson/blob/7.x/LICENSE.txt). [v7.4.3](https://github.com/bblanchon/ArduinoJson/releases/tag/v7.4.3) released **2026-03-02**; release notes describe fixing a buffer overrun when numeric conversion parses a very long floating-point string (issue #2220). This is upstream's claim, not an independent vulnerability reproduction.
- **Source-level reusable pieces:** [JSON deserializer](https://github.com/bblanchon/ArduinoJson/blob/7.x/src/ArduinoJson/Json/JsonDeserializer.hpp) supports nested objects/arrays, filtering and a nesting limit; `JsonSerializer.hpp`; [MessagePack deserializer](https://github.com/bblanchon/ArduinoJson/blob/7.x/src/ArduinoJson/MsgPack/MsgPackDeserializer.hpp); `MsgPackSerializer.hpp`; [ResourceManager](https://github.com/bblanchon/ArduinoJson/blob/7.x/src/ArduinoJson/Memory/ResourceManager.hpp) implements pooled variant/string allocation and overflow state; `Deserialization/deserialize.hpp`; [JsonFilterExample](https://github.com/bblanchon/ArduinoJson/tree/7.x/examples/JsonFilterExample); `extras/tests/` contains deserializer, serializer, memory and integration cases.
- **Upstream execution evidence:** [2026-08-11 default-branch CI run 31512131312](https://github.com/bblanchon/ArduinoJson/actions/runs/31512131312), SHA `1cd478f48`, **46/46 successful jobs**. Matrix includes GCC/Clang/Xcode, AddressSanitizer/UndefinedBehaviorSanitizer/LeakSanitizer configurations, Valgrind, CodeQL, Arduino AVR/SAMD, ESP-IDF, ARM GCC, and multiple PlatformIO boards. This is upstream CI and does not prove runtime behavior on physical boards. Experimental `grisu` runs in October failed; unrelated branch failures are not misrepresented as 7.x failures.
- **Version discrepancy:** `7.x/library.properties` says **7.4.2** whereas `v7.4.3/library.properties` says **7.4.3**. Treat tag/release metadata separately from branch metadata; pin the known fixed release rather than assuming current branch package metadata is current.
- **Recursive ecosystem:** [ESPHome JSON component](https://github.com/esphome/esphome/blob/dev/esphome/components/json/__init__.py) explicitly selects `bblanchon/arduinojson` `7.4.3` for ESP-IDF and `bblanchon/ArduinoJson` `7.4.3` for other builds. This establishes a source-level direct dependency, not a tested device integration. ESPHome itself uses split MIT/GPLv3 licensing; ArduinoJson's MIT does not relicense ESPHome C++ code.
- **Score:** Utility 5, Working Evidence 5, Reusability 5, Novelty 3, Documentation 5, Maintenance 4 = **27 / S**.
- **Follow-up:** Reproduce long numeric-string handling and depth-limit behavior with bounded memory; verify v7.4.3 on ESP32/Termux and inspect dependency resolution when branch manifest is stale.

## OpenZeppelin Contracts — VERIFIED upstream / S28
- **Upstream:** https://github.com/OpenZeppelin/openzeppelin-contracts ; [MIT license](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/LICENSE). [v5.7.0](https://github.com/OpenZeppelin/openzeppelin-contracts/releases/tag/v5.7.0) released **2026-07-29**. Release notes flag `EIP712` long name/version behavior and `ERC2771Forwarder` custom-error rename.
- **Reusable source components:** [ERC20](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC20/ERC20.sol) provides balance/allowance/transfer logic but **does not mint an initial supply**; [AccessControl](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/access/AccessControl.sol) implements role administration with explicit default-admin risk; [ERC1967Proxy](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/proxy/ERC1967/ERC1967Proxy.sol) implements proxy initialization/delegatecall; [MerkleProof](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/utils/cryptography/MerkleProof.sol) implements sorted-pair inclusion and multiproof verification and warns against ambiguous 64-byte leaf preimages; `contracts/governance/`, `test/`, `fv/`.
- **Upstream execution evidence:** [2026-10-30 master checks run 41000334840](https://github.com/OpenZeppelin/openzeppelin-contracts/actions/runs/41000334840), SHA `5b76c00f`, passed **7/7 jobs**: tests, upgradeable tests, coverage, Slither, lint, harness compilation, codespell. [Code Quality 41000334212](https://github.com/OpenZeppelin/openzeppelin-contracts/actions/runs/41000334212) passed. These are **current-master** runs, not tests of exact stable v5.7.0 tag.
- **Audit boundary:** [audits/README.md](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/audits/README.md) enumerates published audit reports through **v5.6.0**, but no v5.7.0 report is listed. The README discusses audited npm `latest` versus `dev` releases; this alone does not establish a version-specific v5.7.0 audit. Upstream security documentation is not a substitute for application-specific audits.
- **Runtime and scope:** Solidity `^0.8.20` in ERC20/MerkleProof, `^0.8.22` in inspected ERC1967Proxy; current `package.json` Node `^22.12 || ^24 || >=26`; use Hardhat/Foundry and an EVM chain. This is **not** a Solana SPL contract library.
- **Recursive ecosystem:** [OpenZeppelin/merkle-tree](https://github.com/OpenZeppelin/merkle-tree) README explicitly pairs off-chain `StandardMerkleTree` proofs with on-chain `MerkleProof`. MIT license verified; stable v1.0.8 published **2025-02-19**. Follow-up to verify interoperability at current Solidity/JS versions; no independent proof generation.
- **Score:** Utility 5, Working Evidence 5, Reusability 5, Novelty 4, Documentation 5, Maintenance 4 = **28 / S**.
- **Follow-up:** Verify upgradeable storage layout and initialization invariants; evaluate ERC20 token supply/roles; test Merkle proof generation against current library versions; inspect exact release-tag CI and audit provenance.
